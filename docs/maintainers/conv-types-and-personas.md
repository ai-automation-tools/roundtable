# Conversation types, presets and personas

> Read before changing `conv_types.py`, `presets.py`, `personas.py` or `model_personas.py`. Moved out of `AGENTS.md` verbatim on 2026-11-22 (audit RT-26) so every agent session doesn't load it; `AGENTS.md` keeps a one-line pointer.

## Conversation types + sub-types (`orchestrator/conv_types.py` + `presets.py`)

- **Two axes, and keeping them separate is the point.** `conv_type` is the room's *structure* — who is in it, what each chair is for. `preset` is the *sub-type* — the tone, and for a type that makes something, the artifact's shape. A structure is expensive (seats, role briefs, a skill, a guide); a flavour is a dict entry. **Only add a `conv_type` when the seats genuinely differ.** Brainstorm / plan / review are presets of `collaborate`, not types, because they're the same room pointed at different work.
- **Adding a type is: a `CONV_TYPES` entry, a `_ROLE_BRIEFS` entry per seat, a `skills/<type>-mode/` (plus its `.gitignore` line), and a `docs/guides/<type>.md` with its row in the Guides index.** The `/orchestrate` radios, the `/conversations` filter chips, export's Type/Role rows, and media prompts all generate from the registry. **No PowerShell edit** — `New-AgentPrompt` is role-agnostic.
- **A type that produces a deliverable** sets `produces_deliverable` + `deliverable_label`; its lead posts the artifact on its closing turn with **`signal='result'`**. That is a `messages.signal` value, deliberately not a column: `signal` already rides the sync, the SSE payload, and export's `` `signal=<value>` `` heading suffix, so a deliverable needs no schema change and **no export-contract change**. `maybe_complete()` must keep stopping on `done`/`blocked` only — a result is not a stop signal.
- **A run may hold several results, and the LAST one wins.** Leads draft-then-revise — every collaboration so far has (#51 six, #54 two), each revision better than the last. `export.final_result()` / `superseded_result_ids()` define last-wins **once**, for the reader, the export and the delivery sink. The export publishes which is current as an **additive `Result` row in `topic.md`**, never as a transcript-heading suffix: the contract says a heading *ends* with the `` `signal=<value>` `` span, so a suffix could break an end-anchored parser. `tests/test_deliverable_flow.py` pins the headings clean.
- **A non-lead cannot `signal='done'` before a result exists** in a `produces_deliverable` type — `blocks_premature_done()` refuses it *before* the insert. Otherwise a collaborator can close a run that produced nothing, and the row still reads `complete`. The lead may always end early, `blocked` is never restricted, and transcript types (debate/podcast) are untouched.
- **A type may declare EXTRA roles beyond the lead and the members** — `ConvType.extra_roles`, a tuple of `ExtraRole(role, label, plural, max_count, hint)`. `roles` is a variable-length tuple, not the old 2-tuple; that limit was what blocked red-team, a differentiated expert panel and the designated skeptic. An extra role **re-brands a member seat, never adds one**: `collaborate`'s optional `skeptic` is one of the collaborators the operator already picked, so nothing about the participant bounds changes. Consequences that are easy to get wrong: it is **never assigned implicitly** (`default_roles()` still only ever produces the lead and the member role, so a caller that says nothing gets the room it always got) · `min_members` counts the **plain** member role, so a facilitator plus a skeptic is refused · the lead cannot also hold one, and `POST /api/orchestrate` says so rather than letting a dict update pick a winner · every extra role needs its own `_ROLE_BRIEFS` entry, which `tests/test_conv_types.py` pins via `ALL_ROLES`. The `/orchestrate` *Special seats* dropdowns and its `roles: {cli: role}` payload generate from the registry — adding one costs no render edit and **no PowerShell edit**.
- **`lead_forces_turns`** decides whether seating a lead overrides the preset's mode. True for a room the lead *runs* (a continuous moderator or host is a free-for-all); False for one it merely *lands* — a collaboration, where `brainstorm` sets `continuous` on purpose. `POST /api/orchestrate` reads it; don't reintroduce an unconditional `mode='turns'`.
- **`lead_needs_own_seat`** says whether the lead is a *participant* or an *observer*. True for a debate's moderator and a podcast's host — neither argues or answers, so `/orchestrate` asks for its **tool** separately (a seat *number* is then derived like any chair's, so it may share a tool with the guests) and prepends the seat. False for a collaboration's facilitator, which is one of the collaborators: the form hides the lead section entirely and the lead is **whoever speaks first**, assigned by `conv_types.default_roles()` from seat order. Getting this wrong deals an unpicked third CLI into a two-agent run. Use `min_participants`/`max_participants` (not `min_members`/`max_members`) anywhere the count includes the lead.
- **`Preset.for_types` is advisory** — it filters the `/orchestrate` picker, exactly like CLI availability does. Nothing rejects an odd pairing, and a preset with no `for_types` is offered everywhere.
- **`Preset.protocol` filters what an agent is SHOWN, never what is stored.** `blind-first` (on `audit`) hides the other agents' messages from an agent's `history` until it has posted once — per agent, not per round, so a stalled seat can't keep the room blind. It lives in `_compute_turn_state()` only; the transcript, SSE, export and delivery must keep seeing every message. It's read from the stored `preset` name, so there is no column and no per-run override.

## Personas (`orchestrator/personas.py` + `model_personas.py`)

- **Groups are free-form** — `discover_groups()` reads `SELECT DISTINCT "group"`; a group exists once a row lands in it. `PREFERRED_GROUPS` is a sort hint, not a filter, and `DEFAULT_DEBATER_GROUP` ("Unique-Personas") currently holds zero rows, which is why the random-cast paths fall through to "every persona".
- **Random casting must go through `list_debater_personas()`**, never `list_personas(None)` — it excludes `RESERVED_GROUPS` so a random debate never fields "Claude Code" against Gordon Ramsay. Callers: `POST /api/orchestrate` and `debate.ps1` via `list --castable`. An explicit `--group` / `-Group` is always honoured.
- **`AI-Models` is a reserved group**: one card per `preflight.SUPPORTED_CLIS` entry, slugged with the agent id, defined in `model_personas.py`, created on web-UI boot by `ensure_model_personas()` (create-if-missing, so operator edits survive a restart). They back the Cast panel when a conversation has no recorded `participant_personas`; recorded personas always win. Bodies are original descriptions, deliberately not copies of any vendor's system prompt.
