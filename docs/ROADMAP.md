The Roundtable roadmap routine (job `agent-chat-roadmap`) works this file top to bottom, one item per run, as `roadmap/auto-` PRs: it takes the first open item under `## After public release` that it can finish and verify on its own (the security block, then High, then Medium, then Low; top to bottom within each), builds it and ticks it. **Every item above `## After public release` is a go-live gate**, and all of them are met: the repo was prepared for public visibility on 2026-09-10 and was public, with a card on ai-automation-tools.dev, by 2026-09-14. Ticking an item appends ` — done YYYY-MM-DD: <what landed>` to its line and, in the same commit, adds the matching entry to the [changelog](CHANGELOG.md) and updates any doc or skill it made stale; [`/close-roadmap-item`](../.claude/commands/close-roadmap-item.md) is the procedure.

Items are records, not scratch: an item is never deleted, and work that only partly landed stays `- [ ]` with a dated `**(YYYY-MM-DD)** …` progress note appended to its line. Each open item says its type in italics after the title.

Markers: `- [ ]` open, `- [-]` claimed by a run in progress, `- [x]` done, `- [!]` blocked (the reason follows on the line). A closed item that reads `— dropped YYYY-MM-DD:` was retired without being done; the reason follows. `` `small` `` marks an item a check verifies; `🔒 Needs owner` marks one only the owner can do.

> Done and dropped items live in the archive, [`docs/roadmap/`](roadmap/README.md): the finished build phases and every item ticked before 2026-11-22. Close an item here in place; the next trim moves it there (audit RT-26).
